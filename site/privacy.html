Privacy Policy

Last updated 27 October 2026 · applies to tabbary 0.8.0 and later

Tabbary is a tab manager for Chrome. This policy describes exactly what the extension can access, what it stores, and what — if anything — leaves your device. It is written to be checked against the source, which is public and MIT-licensed.

The short version. Tabbary stores your tabs in your own browser profile. It makes no network request unless you turn sync on and configure a server. There is no account, no analytics, and no third-party service of any kind.

What tabbary can access

PermissionWhy it is neededWhen
tabs Read tab titles and URLs so a session can be saved and restored. Required
tabGroups Capture and recreate Chrome tab groups. Required
storage, unlimitedStorage Keep sessions, revisions, and local backups in this profile. Required
sidePanel Provide the side-panel view. Required
alarms Schedule autosave coalescing, local backups and (if enabled) sync polling. Required
favicon Show a tab's own icon in lists, using Chrome's local favicon cache. Required
history Optional history features. Only if you enable them. Revocable.
bookmarks Import Chrome's bookmark tree into tabbary. Only when you press “Import from Chrome”.
Host access Reach the sync server you configure. Only the origin you enter. No access at install.

tabbary cannot read page content. It does not request access to the sites you visit, and it does not inject scripts into them.

What is stored, and where

Everything is stored locally in Chrome's extension storage and IndexedDB, inside your browser profile:

  • Sessions — tab titles, URLs, ordering, pinned state, tab groups.
  • Revisions — short history of each session, capped by your setting.
  • Tags and bookmarks you create in tabbary.
  • Backups — automatic snapshots, capped at 17 slots.
  • Settings — your preferences.

If sync is enabled, the extension also stores a device token and an encrypted copy of your sync key. Uninstalling the extension removes all of it from your profile.

Network activity

With sync off (the default), tabbary makes no network requests. Everything — capture, restore, backup, export — happens locally.

If you enable sync, the extension talks only to the server URL you provide:

  • It sends encrypted blobs: ciphertext, an IV, a timestamp, and a blob id.
  • It receives the same. The server cannot decrypt them.
  • It sends a device name you chose, used only to list paired devices.

This project operates no hosted service and collects no data. You point Tabbary at a server you run yourself; that operator holds ciphertext only. Because the key never leaves your device, the operator cannot read your tabs, and cannot reset your passphrase.

What is never collected

  • No account, email address, or identity of any kind.
  • No analytics, telemetry, crash reporting, or usage statistics.
  • No advertising identifiers, and no ad network.
  • No page content, form data, passwords, or cookies.
  • No data sold, rented, or shared with third parties.

Third parties

None. Tabbary loads no remote scripts, fonts, or images. The only hosts it contacts are the sync server you configure yourself.

Your control over the data

  • Export — Settings → Import & export writes plain JSON, or an encrypted file with a passphrase you choose.
  • Delete — remove individual sessions, tags, bookmarks, or backups at any time.
  • Disconnect sync — Settings → Sync & backup → Forget this server removes the token, the keys, and the host permission.
  • Uninstall — removes all locally stored data with the extension.

Children

tabbary is a general-purpose developer tool and is not directed at children under 13.

Changes

Material changes to this policy will be recorded in the project's changelog and the “last updated” date above will change. Because there is no account, there is no mailing list to notify; the repository is the source of truth.
